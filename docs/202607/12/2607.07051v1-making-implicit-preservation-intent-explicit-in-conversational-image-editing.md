## 摘要
对话图像编辑不仅需要保留可见内容，还需要保留跨轮次暂时消失的内容。当新添加或修改的内容遮挡了先前可见的区域时，如果该区域从未被语义更改，它应该重新出现。然而，现有系统往往无法恢复此类被遮挡但未更改的内容，导致不一致或幻觉结果。我们引入了OCCUR-Bench，这是一个用于对话图像编辑中时间保护的诊断基准。OCCUR-Bench提供了多样的遮挡与揭示场景以及历史恢复参考，使得能够评估忠实恢复而非合理再生。我们还提出了ReSpec，这是一个无需训练的框架，通过将恢复感知指令与历史视觉参考配对，使隐式保护显式化。给定编辑历史，ReSpec识别应该保留的内容，选择提供缺失视觉证据的历史图像状态，并基于生成的指令和参考图像条件化上下文编辑器。实验表明，ReSpec在OCCUR-Bench上提高了恢复保真度和时间一致性，强调了将保护基于编辑历史而非仅当前图像的必要性。

## Abstract
Conversational image editing requires preserving not only visible content, but also content that temporarily disappears across turns. When newly added or modified content occludes a previously visible region, that region should reappear if it was never semantically changed. However, existing systems often fail to recover such occluded-but-unchanged content, producing inconsistent or hallucinated results. We introduce OCCUR-Bench, a diagnostic benchmark for temporal preservation in conversational image editing. OCCUR-Bench provides diverse occlusion-and-revelation scenarios with historical restoration references, enabling evaluation of faithful restoration rather than plausible regeneration. We also propose ReSpec, a training-free framework that makes implicit preservation explicit by pairing restoration-aware instructions with historical visual references. Given an editing history, ReSpec identifies what should persist, selects the historical image state that provides missing visual evidence, and conditions an in-context editor on the resulting instruction and reference image. Experiments show that ReSpec improves restoration fidelity and temporal consistency on OCCUR-Bench, highlighting the need to ground preservation in editing history rather than only the current image.

## 1. 核心问题与整体含义
- **研究背景**：对话图像编辑允许用户通过多轮对话迭代地修改图像。一个基本期望是“保留”：用户未要求更改的内容应保持一致。
- **核心问题**：现有系统主要保留当前图像中**可见**的内容。然而，在对话编辑中，内容可能因添加、移动、替换等操作而被**暂时遮挡**，然后在后续轮次中重新出现。如果被遮挡的内容从未被语义更改，它应在重新可见时被忠实恢复。
- **研究动机**：现有系统在此类场景下常常失败，它们仅基于当前图像和指令进行再生，而非基于编辑历史进行恢复，从而产生不一致或幻觉的结果（如图1所示）。这揭示了一个关键限制：**视觉缺失不等于语义改变**。现有基准也未能充分评估这一“时间保留”能力。

## 2. 论文提出的方法论
- **核心思想**：将用户指令中**隐式**的保留意图（即“不要改变什么”）**显式化**，并通过提供**历史视觉证据**来支持恢复。
- **关键技术细节 - ReSpec 框架**：一个无需训练、基于推理的框架，包含三个步骤：
    1.  **保留目标识别**：基于当前指令和编辑历史，使用视觉语言模型（VLM）推理出在当前轮次中**应该被保留（但可能被遮挡）** 的内容描述（`Dt`）。
    2.  **历史参考选择**：当需要恢复被遮挡内容时，VLM从编辑历史中选择一个**包含该内容有效视觉证据**的历史图像状态（`I_ref`）作为参考。
    3.  **恢复感知编辑**：VLM将当前指令（`Pt`）改写为**恢复感知指令**（`~Pt`），其中明确包含需要恢复的目标描述（`Dt`）。然后，一个**支持参考图像输入**的上下文编辑器，以当前图像、改写后的指令和选中的历史参考图像作为输入，生成最终图像。
- **算法流程**：`~Pt = Rewrite_VLM(Pt, Dt)`, `Î_t = f_edit(I_{t-1}, ~Pt, I_ref)`。对于不需要恢复的中间轮次，则不使用历史参考图像。

## 7. 优点
- **问题洞察深刻**：精准地识别并定义了对话图像编辑中一个被忽视但重要的“时间保留”问题。
- **基准设计精巧**：OCCUR-Bench通过精心设计的“遮挡-揭示”场景和明确的评估指标，为该问题提供了一个标准化、可量化的诊断工具。
- **方法设计优雅**：ReSpec是一个**训练免费**的即插即用框架，不修改基础编辑器架构，仅通过增强输入（指令和视觉上下文）来引导编辑，具有很好的通用性和部署便利性。
- **实验全面深入**：不仅报告了总体性能，还从多个维度（轨迹长度、操作类型、区域大小等）进行了细粒度分析，使结论更具说服力。

## 8. 不足与局限
- **对VLM控制器的依赖**：ReSpec的性能高度依赖于VLM控制器（如Qwen3-VL）正确识别保留目标和选择历史参考的能力。控制器的质量直接影响最终效果。
- **额外的推理开销**：引入额外的VLM调用步骤增加了计算成本和延迟，虽然论文声称是训练免费，但在实际部署中需要考虑效率。
- **评估依赖自动工具**：OCCUR-Bench的评估流水线依赖于对象检测（YOLO-Worldv2）和分割（SAM）模型来生成评估掩码，这些工具的错误会影响评估结果的准确性。
- **应用场景局限**：主要针对“遮挡-揭示”这类特定的时间保留问题。对于其他类型的跨轮次不一致性（如风格漂移、属性记忆丢失）是否同样有效，需要进一步验证。
- **历史图像选择策略**：当前总是选择“最近的一个有效历史状态”，但在更复杂的历史中，可能存在多个候选状态，最优选择策略值得进一步探索。
